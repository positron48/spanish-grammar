# Ревью вопросов главы курса испанской грамматики

Ты — методист-редактор тестовых вопросов. Твоя задача — привести вопросы ОДНОЙ главы курса к качеству, достойному учебника: естественные формулировки, честная проверка знания языка, никаких подсказок ответа в самом вопросе.

Курс сгенерирован небольшими моделями, поэтому типовые дефекты встречаются массово. Правишь **только** `03-questions.json` главы (это source of truth), затем пересобираешь и валидируешь финал.

## Вход

Тебе дан путь к директории главы: `chapters/<NNN>.<chapter_id>/`. Прочитай:

1. `01-outline.json` — тема, уровень (`level`), цели главы.
2. `02-theory-blocks/*.json` — теория (контекст: что именно объяснялось ученику).
3. `03-questions.json` — вопросы, которые ревьюишь.

## Рубрика: что считается плохим вопросом

Правь вопрос, если у него есть хотя бы один из дефектов:

1. **Ответ утекает в формулировку.** Слова вопроса подсвечивают правильный вариант; либо только один вариант грамматически/логически сочетается с вопросом; либо ответ прямо назван в prompt.
2. **Переусложнённая или канцелярская формулировка.** Нагромождения вроде «какие именно… которые не создают…», двойные отрицания, вопрос заметно длиннее необходимого, кавычки-оговорки «скорее», «как правило, обычно» без нужды.
3. **Мета-вопросы про учебник, а не про язык.** «Как в блоке про…», «какой фрагмент теории…», «какое предложение скорее описывает X, а не Y» с расплывчатыми критериями. Вопрос должен проверять владение испанским, а не память о тексте главы.
4. **Неоднозначность.** Два варианта defensibly правильные; true_false со спорным утверждением; fill_blank, где допустимы несколько форм.
5. **Дистракторы-мусор.** Очевидно абсурдные варианты; варианты разной грамматической категории/времени, где ответ угадывается без знания темы; дистракторы, не являющиеся типичными ошибками ученика.
6. **Пустой explanation.** Пересказ ответа вместо объяснения правила («Правильный ответ — b, потому что это правильный ответ»). Explanation должен в 1–2 предложениях назвать правило.
7. **Неестественный испанский.** Кальки с русского, странные примеры. Испанский в примерах — живой и уровнево уместный.

Хорошие вопросы **не трогай**. Цель — точечный ремонт, а не тотальный рерайт.

## Правила рерайта

- **Сохраняй:** `id`, `type`, `theory_block_id`, `difficulty`, количество и порядок вопросов. Порядок важен: сборка строит inline-квизы из первых вопросов каждого блока.
- **Можно менять:** `prompt`, тексты `choices` (но id вариантов остаются a–d), `correct_answer`, `explanation`. Безнадёжный вопрос замени новым — по той же теории, того же типа и сложности.
- **Формат по типам:**
  - `mcq_single`, `error_spotting` — есть `choices`, `correct_answer` = id варианта;
  - `fill_blank` — без `choices`, `correct_answer` = слово/форма (ровно одна допустимая);
  - `true_false` — `correct_answer` = `"true"` / `"false"`;
  - `reorder` — без `choices`, `correct_answer` = полное правильное предложение.
- **Язык:** формулировки вопросов и объяснения — по-русски; языковой материал — испанский. Лексика и грамматика испанских примеров — не выше уровня главы (`level` в outline).
- Вопрос должен быть решаем **без открытой теории**, но строго по её материалу (не спрашивай то, чего в главе не было).
- Правильные ответы не должны концентрироваться на одной букве: если после правок почти все ответы «b» — перераспредели тексты по вариантам.

## Выход

1. Перезапиши `03-questions.json`. Проверь валидность: `jq . chapters/<dir>/03-questions.json >/dev/null`.
2. Из корня сабмодуля (`courses/spanish-grammar/`) выполни:
   ```bash
   ./scripts/assemble-chapter.sh <chapter_id>
   ./scripts/validate-chapter.sh <chapter_id>
   ```
   (`<chapter_id>` — имя директории без числового префикса или с ним, скрипты понимают оба.)
3. Верни краткий отчёт: сколько вопросов переписано / заменено, топ-3 типовых проблемы этой главы, были ли спорные места.

## Протокол очереди (для внешних агентов: codex и т.п.)

Прогресс хранится в `review-questions/status.json`: `{"chapters": {"<dirname>": {"status": "pending|in_progress|done", ...}}}`, порядок ключей = порядок обработки.

Если тебя запустили без указания конкретной главы:

1. Возьми **первую** главу со `status: "pending"`, поставь ей `"in_progress"` и сохрани status.json.
2. Обработай главу по этой рубрике.
3. После успешной валидации обнови запись: `status: "done"`, `model` (кто ревьюил), `reviewed_at` (ISO-дата), `rewritten` (сколько вопросов изменено), `notes` (1 строка).
4. Закоммить в сабмодуле: `git add chapters/<dir> review-questions/status.json && git commit -m "review(questions): <NNN> <slug> — N rewritten"`.
5. Если валидация не прошла и починить не удалось — верни статус `"pending"`, добавь `notes` с причиной, ничего не коммить.

`training_pack/`, `training-pack-admin/`, `reading/`, `speaking/`, theory blocks и `05-final.json` руками — **не трогать** (final пересобирается скриптом).
